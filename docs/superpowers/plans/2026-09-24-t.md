## Decisions and deviations (read before coding)

1. **Shared words live in new T files, never in K's.** `utils/asOf.ts` is K's; its day label is
   private. `utils/timeWords.ts` (new) exposes `dayName` ("Oct 1", ", 2025" outside the server's
   year — implemented THROUGH `formatAsOf`, so the two can never disagree), `monthName`
   ("September", " 2025" outside the year), `dueByIso`/`dueByName` (the day before `overdue_from`,
   K3's "due by" rule). `components/networth/snapshotStates.ts` (new) mirrors K2's current-snapshot
   rule for a timeseries a page already holds (`currentSnapshotIndex`) and turns the wire lists into
   `Dated` states (`snapshotAt`, `summaryState`); a payload without the new lists (a replayed cache,
   an old fixture) reads final, as of its 1st — additive tolerance, not a second rule.
2. **Spending gets `flows_due` from its scope row.** The spec says "the pages pass `time.flows_due`
   from the coverage they already fetch"; Spending never fetched coverage — its `ScopeBar` does.
   `ScopeBar` gains `onCoverage?: (coverage) => void` (called with every answer it lands) and the
   page seeds from the shell snapshot (`COVERAGE_SNAPSHOT`), so no second `/coverage` request is
   made. Inside `SpendingPage.tsx` the edits are exactly: that state + prop, the `flowsDue` input to
   the chart options and footnotes, `defaultMonth`/`backLabel` on the ScopeBar, and the two new
   BudgetPanel props (controller assignment 1).
3. **Budgets view (controller assignment 1).** `BudgetPanel` gains two optional props (additive):
   `flowsDue` (the month shown reads "Partly entered" / "Not entered yet" with the due date instead of
   a complete month's "0 of 13 over") and `onShownMonth` (reports the month it resolved, so the page's
   ScopeBar `defaultMonth` on the Budgets view is "its resolved month", T8 — a callback in an effect,
   because the pin after a write lives inside the card). No edit to `budgets.css` or `budgetMonth.ts`.
4. **T5 `check_coverage_gaps` — each half by its own threshold.** The spec: "excludes a month whose
   flows are not yet overdue". Applied to the half whose missing part IS the flows
   (`balances_without_spending`: only months ≤ `overdue_through(today, reminder day)`). The other half
   (`spending_without_balances`) is missing BALANCES, whose threshold is capped at the month's last
   day, so every ended month is already overdue — it keeps `< current month`. Same intent (no
   premature alert), no false silence on a month whose balances really are late.
5. **T6 bounds.** A month before the first snapshot month is never pending (K3's windows start at
   the first snapshot); a book with no snapshot at all is asked for its first balances (the old
   generator's always-on behaviour, and `compose`'s empty-sources test keeps its `update_due`). The
   event `detail` is `None` until re-dated (the items carry the per-part details), then "Due since
   {Oct 1}", then "Overdue — {parts} {was/were} due {Oct 1}". `Sources.entered_months` is replaced by
   `Sources.month_status: MonthStatus | None` (internal dataclass, not a payload).
6. **T8 words gain a due tail.** The ribbon's due/overdue dot is colour; its text twin rides the
   aria-label/tooltip: "… · take-home missing · due by Oct 15" / "· overdue (was due by Oct 15)" —
   appended after K3's literal words.
7. **T3 overdue wording with take-home also missing.** K3 gives "{September} spending is still
   partial — was due {Oct 15}"; when the take-home is ALSO missing the line says so: "{September}
   spending is still partial and its take-home is missing — was due {Oct 15}". Spending missing but
   take-home in: "{September} spending is overdue".
8. **T4 tails.** Spending/Net pay: "{latest} · {cur} in progress · {newest pending} partly entered —
   due|overdue" (or "· {m} due|overdue"), and the OLDER pending months after the latest entered one
   in the existing parenthetical grammar ("(Sep partly entered, Oct missing, Nov missing)", capped at
   three, calendar order, the clause's year elided). Without `time` (empty book, older backend) the
   clauses are presence-only and never amber — the old "≥ 1 month behind balances" amber is exactly
   the false alarm T4 removes.
9. **T2 edge words.** A provisional base (Jan 1 recorded early, never re-saved) reads "since Dec 28,
   2026 (provisional)"; a current snapshot BEFORE the year's first snapshot (only a far-future filing
   can do that) reads like "no snapshot keyed in the year". The through-date for an unknown as-of
   reads "(to date unknown · provisional)" (asOfPhrase's words).
10. **T7 extras by the same rule:** the What-moved lede ("Sep 1 $X → Oct 1 $Y") and the Accounts card
    heading ("Accounts — as of Sep 22 · provisional") are dated too — otherwise they contradict the
    dated title beside them. The page relies on T8's ScopeBar default anchor (max(current month,
    current snapshot month)) rather than passing its own.
11. **Tests pin the day where a label carries the year rule.** Labels such as "as of Aug 1" gain ",
    2026" once the server's year moves on; suites that pin literals call `setServerToday(…)` (the

def _joined(months: list[date]) -> str:
    labels = [_label(m) for m in months]
    return labels[0] if len(labels) == 1 else f"{', '.join(labels[:-1])} and {labels[-1]}"


def check_future_snapshot(status: MonthStatus) -> HealthCheckOut:
    """Balances filed more than a month ahead (2026-09-23 spec §T5). The current snapshot is the
    latest one up to next month (§0.4(b)), so these are never your balances — only an API client
    or a workbook import can store them, and no other surface says where they went."""
    bound = month_shift(status.current_month, 1)
    ahead = [state.month for state in status.snapshots if state.month > bound]
    if not ahead:
        return _ok("future_snapshot", "No balances filed ahead of their month")
    first = ahead[0]
    return HealthCheckOut(
        id="future_snapshot",
        severity="warn",
        title="Balances filed ahead of their month",
        detail=(

            "your current balances. Delete them or file them under the right month."
        ),
        count=len(ahead),
        months=ahead,
        fix=HealthFixOut(
            kind="link",
            to=f"/update?month={first.isoformat()}&step=balances",
            label=f"Open {_label(first)} balances",
        ),

```python
@dataclass(frozen=True)
class _Part:
    label: str
    detail: str
    overdue_from: date
    plural: bool  # "Oct 1 balances were" / "September spending & take-home was"

def _day(value: date, today: date) -> str:
    label = f"{_MONTH_NAMES[value.month - 1][:3]} {value.day}"
    return label if value.year == today.year else f"{label}, {value.year}"

def _month(value: date, today: date) -> str:
    name = _MONTH_NAMES[value.month - 1]
    return name if value.year == today.year else f"{name} {value.year}"

def _first_month(status):  # the book's first snapshot month, or None
    return status.snapshots[0].month if status is not None and status.snapshots else None

def _balances(month, status, due_day, today):
    snapshot = None if status is None else status.snapshot(month)
    if snapshot is not None and not snapshot.provisional:
        return None
    first = _first_month(status)
    if first is not None and month < first:
        return None  # before the book began; an empty book is asked for its first balances
    if snapshot is None:
        detail = "not recorded yet"
    elif snapshot.recorded_on is not None and snapshot.recorded_on < month:
        detail = f"recorded early, on {_day(snapshot.recorded_on, today)} — update them"
    else:
        detail = "recorded ahead of their date — update them"
    return _Part(f"{_day(month, today)} balances", detail, balances_overdue_from(month, due_day), True)

def _flows(month, status, due_day, today):
    ended = month_shift(month, -1)
    first = _first_month(status)
    if first is None or ended < first:
        return None
    spending, take_home = status.spending_state(ended), status.take_home_entered(ended)
    if spending == "entered" and take_home:
        return None
    name = _month(ended, today)
    if spending == "missing":
        detail = "spending not entered" if take_home else "not entered"
    else:
        clauses = [f"entered during {name}; add what has posted since"] if spending == "partial" else []
        if not take_home:
            clauses.append("take-home not entered")
        detail = " · ".join(clauses)
    return _Part(f"{name} spending & take-home", detail, flows_overdue_from(ended, due_day), False)

def ritual_events(window, today, due_day, status):
    events = []
    for month in window.months():
        nominal = date(month.year, month.month, due_day)
        parts = [p for p in (_balances(month, status, due_day, today),
                             _flows(month, status, due_day, today)) if p is not None]
        if not parts:
            continue
        redated = nominal < today
        event_date = today if redated else nominal
        if not window.contains(event_date):
            continue
        due = _day(month, today)
        detail = None
        if redated:
            overdue = [p for p in parts if today >= p.overdue_from]
            verb = "were" if len(overdue) > 1 or (overdue and overdue[0].plural) else "was"
            detail = (f"Overdue — {' and '.join(p.label for p in overdue)} {verb} due {due}"
                      if overdue else f"Due since {due}")
        events.append(make_event(
            event_date, "update_due", month_shift(month, -1).strftime("%Y-%m"),
            "Monthly update — " + " · ".join(p.label for p in parts), "Monthly update",
            detail=detail, basis="scheduled", href="/update", key_date=nominal,
            items=tuple(Item(p.label, None, None, p.detail) for p in parts)))
    return events
```
