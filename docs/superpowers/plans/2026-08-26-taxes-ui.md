# Taxes Page UI: Filing Status Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

> **RECONCILIATION DECISIONS (orchestrator, 2026-08-26 — authoritative; these RESOLVE the ⚠ assumed-interface table below, and the backend now exists on main so verify against real code where in doubt):**
> 1. Year status is **`PATCH /api/v1/taxes/years/{year}`** with body `{"filing_status": ...}` → updated `TaxYearOut`. Wherever this plan says `putTaxYear`/PUT, implement `patchTaxYear`/PATCH; adjust the single test pin the ⚠ table names.
> 2. Brackets **PUT carries `filing_status` in the JSON body** (`{"filing_status": ..., "jurisdictions": {...}}`). Brackets **GET `?filing_status=` defaults to `'single'` when absent — NOT the year's own status**: the UI must always pass the active tab's status explicitly on every fetch.
> 3. The brackets payload DOES carry **`statuses_with_rows: list[string]`** (required field) — use it for the tab set exactly as written.
> 4. Clone is **query param `target_status`** (`POST .../clone-brackets-from/{src}?target_status=married_joint`), not a JSON body. Omit the param entirely for the legacy path.
> 5. The inputs PUT sibling is named **`rows`** (`{"values": {...}, "rows": [{key, person_id, value}]}`) — same item shape this plan already uses, different field name than the ⚠ table's `person_values`. Rename accordingly, including test pins.

**Goal:** Make the Taxes page speak filing status. The tax-year card gains a Single / Married-filing-jointly / Married-filing-separately selector that PUTs the year's status and reloads its three payloads through the page's existing `selection`-identity trick, with a standing California community-property caveat under MFS. `InputsForm` splits the per-person keys (salary, the W-2 family, 401k, HSA, pre-tax deductions, and the two tracker-only withholding keys) into two named columns on a married year — person-qualified cell ids, person-qualified paste, `person_id` on the wire — while a single year renders **byte-identically to today**. `BracketsEditor` grows status tabs above its six jurisdiction tables, each tab loading/replacing that status' tables, with a "Clone from `<year>` single tables" button on an empty non-single tab and per-jurisdiction review badges from the clone response. `SummaryPanel` replaces the waterfall with a call-to-action when the engine reports `brackets_missing_for_status`, and drops flagged years out of the multi-year trend instead of drawing them as real-looking zeros.

**Architecture:** No new page and no new component file — five existing files carry the whole feature, and every new shared word (jurisdiction labels, filing-status labels, the status order) lands **once** in `src/api/taxes.ts` beside `JURISDICTIONS`, so the editor's table heading and the summary's call-to-action can never name the same table differently. The page stays the single owner of the three-payload load (`TaxesPage.tsx:139-161`) and of the year list, so the status selector is just a **fifth reload door** beside chips / Retry / create / delete: it goes through the same `confirmDiscard()` gate and the same `loadYear()`, whose fresh `{year}` object is what re-runs the load effect for the year already on screen. `InputsForm`'s internal vocabulary moves from *item* to **cell** — one editable box, either the household row for a key or one person's row — and a cell's id is the bare `key` when it is a household cell (exactly the id a single year rendered before this plan) and `key:personId` when it is a person cell. Because a single-status year produces only household cells, the flat list, the DOM ids, the paste targets and the PUT body are all unchanged for it. `BracketsEditor` keeps one status' tables in state at a time, seeded from the page's payload and swapped by its own fetch on a tab press. Every response field this plan reads that the backend does not yet send degrades to a safe default (`?? 'single'`, `?? []`), and `brackets_missing_for_status` is typed **optional** on purpose so the repo's six existing `TaxSummaryOut` fixture builders — including the pinned golden ones in `taxChartOptions.test.ts` and `overviewChartOptions.test.ts` — keep compiling untouched.

**Tech Stack:** React 19 + TypeScript 5.9 (strict, `noUnusedLocals`) + Vite 6, Vitest 3 + @testing-library/react 16 in jsdom, plain CSS custom properties (`--warn`, `--muted`, `--border`, `--surface-2`). No new dependencies, no new npm scripts, no backend work in this plan.

**Spec:** `docs/superpowers/specs/2026-08-26-household-foundation-married-taxes-design.md` §5.4, §5.5, §6 ("Taxes page" bullets) and `docs/superpowers/specs/2026-08-26-marriage-readiness-audit.md` §3.2 (attachment points). Cite them for any ambiguity. Do **not** flip either spec's status line — they cover a six-plan batch and this is plan 5 of 6.

## Preconditions — merged before this plan starts

Treat all of the following as **existing backend behavior**. They come from plan 4 (tax schema + engine) and plan 2 (household foundation), quoted from the design spec:

- `tax_years.filing_status` — `String(20) NOT NULL default 'single'`, one of `single | married_joint | married_separate`, Python-validated like `group`. History untouched; the user flips 2026 in the UI. (§4)
- `tax_brackets.filing_status` — `String(20) NOT NULL default 'single'`; unique becomes `(year, jurisdiction, filing_status, bracket_index)`. All existing rows became `'single'`. (§4)
- `tax_inputs.person_id` — nullable FK → people; unique `(year, key, person_id)` NULLS NOT DISTINCT. `tax_input_definitions.is_per_person` flags **19** keys (the 17 from audit §3.2 plus the two tracker-only ones). "NULL strictly means household-level." (§4)
- **Inputs API:** "`GET/PUT /years/{y}/inputs` rows gain `person_id`; assembly for the engine: household keys from NULL rows, per-person keys summed across person rows… **Single years keep exactly one person column (primary), so existing clients/tests see today's shapes.**" (§5.4)
- **Brackets API:** "`PUT /years/{y}/brackets` gains `filing_status` (full-replace stays per (jurisdiction, status))." (§5.5)
- **Clone API:** "`POST /years/{y}/clone-brackets-from/{src}` gains `target_status`: clones all six jurisdictions **from the source's single tables** to the target status verbatim, and the response flags which tables are typically correct as-is (social_security, disability — per-person parameters) vs need threshold edits (federal, state, capital_gains, medicare's additional tier). 409 only if the target (year, status) already has rows." (§5.5)
- **Summary:** "When a year's status has no bracket tables, the summary returns an explicit `brackets_missing_for_status` state (per-jurisdiction list) instead of computing garbage or 500ing; the UI renders it as a call-to-action." (§5.3)
- **Household API:** `GET /api/v1/household` → people + marriage_date; `POST /people`; `PATCH /people/{id}`; `PUT /marriage-date`. (§5.1)
- **Tracker-only keys:** `w2_fed_withholding` / `w2_state_withholding` are "two new **per-person**, tracker-only input keys… stored like `capital_loss_deductions`: real inputs, never in `ENGINE_INPUT_KEYS`." (§5.6) They arrive in the sections feed like any other key and this plan gives them **no special case at all** — they render as normal per-person inputs.

## ⚠ Interfaces this plan ASSUMED — reconcile against the backend plan before merging

The backend plan file `docs/superpowers/plans/2026-08-26-tax-schema-engine.md` **did not exist** when this plan was written, so the four contracts below are this plan's own choices. Each is isolated in exactly one function so reconciling is a one-line edit. If the backend plan says otherwise, change the function and the matching pin in `src/api/taxes.test.ts` — nothing else in this plan reads a URL or a body shape.

| # | Assumed contract | Isolated in | If the backend disagrees |
|---|---|---|---|
| 1 | **`PUT /api/v1/taxes/years/{year}`** body `{"filing_status": "married_joint"}` → **200 with the updated `TaxYearOut`** | `putTaxYear` in `src/api/taxes.ts` | A `PATCH` verb, or a 204: change `method`, and on 204 replace the `.then((row) => setYears(...))` in `TaxesPage.changeFilingStatus` with a `reconcileYears()` call |
| 2 | **`GET /brackets?filing_status=<s>`**; the param **absent means the YEAR's own status** (which is what a plain year load wants), and the response carries `filing_status` + `statuses_with_rows` | `fetchTaxBrackets` in `src/api/taxes.ts` | If absent means `'single'` instead, pass the status explicitly from `TaxesPage`'s load effect; if `statuses_with_rows` is not sent, `BracketsEditor`'s tab set degrades to `single + the year's status` via the `?? []` already written into the code |
| 3 | **Clone** takes a JSON body `{"target_status": "..."}`, **omitted entirely** when no status is named (so today's new-year clone is byte-identical on the wire), and answers `TaxBracketsOut & {review_flags: {verbatim_ok, review}}` | `cloneBrackets` in `src/api/taxes.ts` | A query param instead: swap the body for `?target_status=` in that one function |
| 4 | **Inputs PUT** stays `{"values": {...}}` for household keys and single-status years, and adds an **optional** sibling `"person_values": [{"key", "person_id", "value"}]` for a married year's per-person columns. A key present in `person_values` is never also in `values` | `InputsForm.submit` builds it; `TaxInputsUpdate` types it | If the backend wants one uniform row list, change `submit()` to emit rows for every cell and update the four existing wire pins in `InputsForm.test.tsx` / `TaxesPage.test.tsx` |

Two smaller judgement calls, both deliberate:

- **Cell id scheme.** The design sketch suggested `` `${key}:${personId ?? 'household'}` ``. This plan uses **`key` for a household cell and `key:personId` for a person cell** instead, because that keeps a single-status year's DOM ids (`tax-input-annual_salary`) exactly as they are today — the "zero visual diff" requirement extends to the ids the paste layer compares. Tax keys are snake_case identifiers and can never contain a colon, so the scheme is still unambiguous. Nothing may look these ids up with a CSS selector (`#a:b` would need escaping); the positional paste compares `input.id` as a plain string, which is safe.
- **"Fall back to Me/Partner".** Interpreted as: a roster person whose `name` is blank is headed "Me" (first column) / "Partner" (second). A roster that failed to load, or that has fewer than two people, renders the form **single-column** — the honest degrade, because there are no real `person_id`s to write with, and an unqualified per-person key is resolved onto the primary person server-side (§5.4). A sentence pointing at Settings → Household says so.

## House rules that bind every task

1. **Server sentences render verbatim** — `err instanceof ApiError ? err.message : '<our own fallback>'`, never re-worded.
2. **Money and rates stay Decimal strings** end to end; nothing is re-derived from a rendered figure.
3. **Comments explain constraints, not narration** — every non-obvious line says *why*, in the voice the surrounding file already uses.
4. **No `setState` in an effect's synchronous body** (react-hooks 7) — promise callbacks only.
5. **A single-status year is the regression suite.** Any change that alters what a single-status year renders, requests or PUTs is a bug in this plan, not a decision.
6. Commit after every task. Never push. No file deletions.

Edit `src/types/api.ts`. Replace the block that currently starts at `:415` (`// --- taxes ---`) down through `TaxSummariesOut` at `:526` so it reads:

```ts
// --- taxes ---
// Money, rates and effective rates are pydantic Decimals on the wire — JSON strings, at
// the quantum the router picked: inputs 4dp, bracket rates 4dp, thresholds 2dp, summary
// money 2dp, effective rates 6dp.

// How ONE year is filed, and which of a year's bracket tables a request means. Mirrors the
// backend's Python-validated String(20) columns (`tax_years.filing_status`,
// `tax_brackets.filing_status`), whose NOT NULL default is 'single' — so every row that
// existed before the marriage migrations is a single filer and history is untouched.
export type FilingStatus = 'single' | 'married_joint' | 'married_separate'

export interface TaxYearOut {
  year: number
  notes: string | null
  input_count: number
  bracket_count: number
  filing_status: FilingStatus
}

// PUT /taxes/years/{year} — the year row's one mutable field. Flipping it changes which
// bracket tables the engine walks, whether the per-person inputs split into two columns,
// and therefore every figure on the page: the caller reloads the year afterwards.
export interface TaxYearUpdate {
  filing_status: FilingStatus
}

// One person's stored row for a per-person key. Absent from the array entirely when that
// person has no row yet — a reader must never assume one entry per household member.
export interface TaxInputPersonValueOut {
  person_id: number
  value: string | null
}

export interface TaxInputItemOut {
  key: string
  label: string
  sort_order: number
  is_derived: boolean
  value: string | null
  // The sheet's gray-cell formula for this key, when it has one. Advisory: the UI offers
  // a chip, nothing is ever applied server-side. Present-ness (not is_derived) is what a
  // chip renders on. Derived suggestions are the PRIMARY person's (design §5.3), so a
  // married row offers exactly one chip.
  suggested: string | null
  // Definition flag (`tax_input_definitions.is_per_person`): this key is stored once per
  // PERSON — salary, the W-2 family, 401k, HSA×2, pre-tax deductions, and the two
  // tracker-only withholding keys. Household keys (interest, dividends, itemized
  // deductions, LTCG…) are stored once, with a NULL person_id.
  is_per_person: boolean
  // The per-person rows behind this key, primary first. Empty for a household key AND for a
  // per-person key nobody has filled in yet; `value` above stays the single-column figure
  // (the household row, or the person rows summed).
  person_values: TaxInputPersonValueOut[]
}

export interface TaxInputSectionOut {
  section: string
  items: TaxInputItemOut[]
}

export interface TaxInputsOut {
  year: number
  sections: TaxInputSectionOut[]
}

// One person-qualified write. Only a married year's per-person columns emit these; the
// `values` map below is what a household key and every cell of a single-status year use.
export interface TaxInputPersonValueIn {
  key: string
  person_id: number
  value: string | null
}

// PUT body — keys unknown to the definition table are a 422, and a null VALUE unsets
// (deletes) that stored input rather than storing a 0.
export interface TaxInputsUpdate {
  // The server resolves each key's person itself: NULL for a household key, the PRIMARY
  // person for a per-person one. This is the whole body a single-status year sends.
  values: Record<string, string | null>
  // Person-qualified writes. A key that appears here must NOT also appear in `values`.
  person_values?: TaxInputPersonValueIn[]
}

export interface TaxBracketOut {
  bracket_index: number
  rate: string
  threshold: string
}

// The PUT element. `bracket_index` is renumbered server-side on every replace and a
// round-tripped one is ignored, so an edited TaxBracketOut VARIABLE can be handed straight
// back (a fresh object literal carrying bracket_index trips excess-property checking).
export interface TaxBracketIn {
  rate: string
  threshold: string
}

// A Record, not a fixed key set: the six known jurisdictions are always present, and an
// importer-written extra one survives a read. Drive render order from `JURISDICTIONS`
// (src/api/taxes.ts) and append whatever else came back.
export interface TaxBracketsOut {
  year: number
  jurisdictions: Record<string, TaxBracketOut[]>
  // WHICH status' tables these are.
  filing_status: FilingStatus
  // Every status with at least one bracket row for this year — the editor's tab set, so an
  // MFJ table entered ahead of the wedding stays reachable from a year still filed single.
  statuses_with_rows: FilingStatus[]
}

// Per-jurisdiction FULL REPLACE: a jurisdiction absent from the body is untouched, and
// an empty array deletes its table. Unknown jurisdiction names are a 422. The replace is
// scoped to (jurisdiction, status): saving Federal for MFJ never touches single's Federal.
export interface TaxBracketsUpdate {
  jurisdictions: Record<string, TaxBracketIn[]>
  filing_status: FilingStatus
}

// Which cloned tables are usually right as they landed, and which need edits. Social
// Security's wage base and SDI's rate/cap are per-person parameters that do not move with
// filing status, so the copy IS the answer; federal, state, capital gains and Medicare's
// additional tier are status thresholds and are only a starting shape.
export interface BracketCloneReviewFlags {
  verbatim_ok: string[]
  review: string[]
}

export interface TaxBracketsCloneOut extends TaxBracketsOut {
  review_flags: BracketCloneReviewFlags
}

export interface IncomeTaxOut {
  agi: string
  taxable_income: string
  tax: string
  effective_rate: string | null
}

export interface WageTaxOut {
  w2_income: string
  taxable_wages: string
  tax: string
  effective_rate: string | null
}

export interface CapitalGainsTaxOut {
  taxable_income: string // the ordinary income the gains stack on top of
  gains_amount: string
  tax: string
  effective_rate: string | null // null when there are no gains (the sheet's #DIV/0!)
}

export interface TaxTotalsOut {
  gross_income: string
  total_income: string
  total_tax: string
  take_home: string
  effective_rate: string | null
}

export interface TaxSummaryOut {
  year: number
  federal: IncomeTaxOut
  state: IncomeTaxOut
  medicare: WageTaxOut
  social_security: WageTaxOut
  disability: WageTaxOut
  capital_gains: CapitalGainsTaxOut
  totals: TaxTotalsOut
  warnings: string[]
  // Jurisdictions with NO bracket table for this year's filing status. OPTIONAL on purpose:
  // it is a state the engine only started reporting with the marriage batch, and typing it
  // required would break a dozen pinned golden fixtures that predate it. Non-empty means
  // the figures above are the engine REFUSING to compute against another status' tables,
  // not an answer — render the call-to-action, never the waterfall.
  brackets_missing_for_status?: string[]
}

export interface TaxSummariesOut {
  years: TaxSummaryOut[]
}

// --- household ---
// GET /api/v1/household. `person_id` NULL anywhere in the app means joint/household; a
// person row is the other case. Exactly one person is primary (partial unique index), and
// there is no delete endpoint this batch.

export interface PersonOut {
  id: number
  name: string
  is_primary: boolean
}

export interface HouseholdOut {
  people: PersonOut[]
  // ISO date, or null before the household card sets it. Unused by the taxes page.
  marriage_date: string | null
}
```

```tsx
const SECTION_LABELS: Record<string, string> = {

  capital_gains: 'Capital gains',

/** One person's column, with the name it is headed by. */
interface Column {
  person: PersonOut
  name: string
}

/**
 * ONE editable box: a key on the household row, or a key on one person's row. `id` is the
 * bare key for a household cell — byte-identical to the id a single-status year rendered
 * before columns existed — and `key:personId` for a person cell. Tax keys are snake_case
 * identifiers and can never contain a colon, so the scheme stays unambiguous; nothing may
 * look these ids up with a CSS SELECTOR (`#a:b` would need escaping), and nothing does — the
 * positional paste compares `input.id` as a plain string.
 */
interface Cell {
  id: string
  key: string
  personId: number | null
  /** The item's own label: what an error sentence and a keyed paste match on. */
  itemLabel: string
  /** null on a household cell; the column's name on a person cell. */
  personName: string | null
  value: string | null
}

function cellId(key: string, personId: number | null): string {
  return personId === null ? key : `${key}:${personId}`
}

/** The accessible name of one box. Two boxes carry the same item label, so they need more. */
function cellLabel(cell: Cell): string {
  return cell.personName === null ? cell.itemLabel : `${cell.itemLabel} — ${cell.personName}`
}

/** "Me"/"Partner" only when the roster carries no usable name for that column. */
function columnName(person: PersonOut, index: number): string {
  const named = person.name.trim()
  if (named !== '') return named
  return index === 0 ? 'Me' : 'Partner'
}

/** Primary first, then by id: the order the columns draw and the order a paste walks. */
function columnsOf(people: PersonOut[]): Column[] {
  return [...people]
    .sort((a, b) => Number(b.is_primary) - Number(a.is_primary) || a.id - b.id)
    .map((person, index) => ({ person, name: columnName(person, index) }))
}

/**
 * The cells one item renders. A household key, a single-status year and a roster that never
 * answered ALL produce exactly one cell whose personId is null — which is what keeps a
 * single-status year's DOM, paste targets and PUT body identical to today's.
 */
function cellsOf(item: TaxInputItemOut, columns: Column[]): Cell[] {
  if (columns.length === 0 || !item.is_per_person) {
    return [
      {
        id: cellId(item.key, null),
        key: item.key,
        personId: null,
        itemLabel: item.label,
        personName: null,
        value: item.value,
      },
    ]
  }
  return columns.map(({ person, name }) => ({
    id: cellId(item.key, person.id),
    key: item.key,
    personId: person.id,
    itemLabel: item.label,
    personName: name,
    // A person with no row yet is absent from the array — never assume one entry each.
    value: item.person_values.find((row) => row.person_id === person.id)?.value ?? null,
  }))
}

  return inputs.sections.flatMap((section) =>

  for (const cell of cells) values[cell.id] = cell.value ?? ''
  return values
}

  const columns = filingStatus !== 'single' && people.length >= 2 ? columnsOf(people) : []

        // The note described a pending fill that the echo just replaced — it would be
        // narrating values that are no longer on screen.
        setPasteNote(null)
        onSaved(echo)
      })
      .catch((err: unknown) => {
        // Includes the Apply-then-save path: a suggestion is an unbounded engine output,
        // so it can legitimately exceed the 10^10 input bound. The edits stay on screen.
        setError(err instanceof ApiError ? err.message : 'Save failed')
      })
      .finally(() => setSaving(false))
  }

  // Range paste (spec §4.1): this FORM owns the values record, so the scope container does
  // the filling — an AmountInput cannot write its siblings. A single-cell clipboard
  // classifies as null and falls through to native insertion, which the tolerant parse
  // already handles. Pasted text lands RAW, exactly as if typed: garbage shows the standard
  // .invalid, and canonicalAmount at the wire boundary is still what the server sees.
  const handlePaste = (e: ClipboardEvent<HTMLFormElement>) => {
    const plan = classifyPaste(e.clipboardData.getData('text/plain'))
    if (plan === null) return
    e.preventDefault()
    const fills: Record<string, string> = {}
    const flashed = new Set<string>()
    const unmatched: string[] = []
    let overflow = 0
    // An empty pasted cell SKIPS its target instead of blanking it: a blank here is the
    // wire's "unset this input", and a stray trailing tab must never delete a stored value.
    let blank = 0
    if (plan.mode === 'positional') {
      // Fill from the pasted-into cell onward, down the rendered order — across section
      // boundaries, the way Enter walks it.
      const target = (e.target as HTMLElement).closest<HTMLInputElement>('input[data-entry-cell]')
      const startAt =
        target === null
          ? 0
          : Math.max(
              0,
              flatCells.findIndex((cell) => `tax-input-${cell.id}` === target.id),
            )
      plan.values.forEach((value, i) => {
        const slot = startAt + i
        if (slot >= flatCells.length) {
          overflow += 1
          return
        }
        // The slot is consumed either way — a skipped blank must not shift the rest up.
        if (value === '') {
          blank += 1
          return
        }
        fills[flatCells[slot].id] = value
        flashed.add(flatCells[slot].id)
      })
    } else {
      // matchLabel keys on numeric ids, so the INDEX into flatCells serves as one.
      const labelled = flatCells.map((cell, i) => ({ id: i, name: cell.itemLabel }))
      for (const { label, value } of plan.rows) {
        const index = matchLabel(labelled, label)
        if (index === null) {
          unmatched.push(label)
        } else if (value === '') {
          blank += 1
        } else {
          fills[flatCells[index].id] = value
          flashed.add(flatCells[index].id)
        }
      }
      overflow = plan.skipped
    }
    if (Object.keys(fills).length > 0) setValues((current) => ({ ...current, ...fills }))
    setFlashIds(flashed)
    const parts = [`Pasted ${Object.keys(fills).length} of ${flatCells.length} values`]
    if (unmatched.length > 0) {
      const shown = unmatched.slice(0, 4).join(', ')
      const more = unmatched.length > 4 ? `, +${unmatched.length - 4} more` : ''
      parts.push(`${unmatched.length} unmatched: ${shown}${more}`)
    }
    if (overflow > 0) parts.push(`${overflow} value${overflow === 1 ? '' : 's'} didn't fit`)
    if (blank > 0) parts.push(`${blank} blank${blank === 1 ? '' : 's'} skipped`)
    setPasteNote(parts.join(' · '))
  }

  return (
    <section className="card">
      <h2 className="eyebrow">
        Tax inputs — {inputs.year}
        <InfoHint text="The year&apos;s income and deduction line items — the old sheet&apos;s white cells. Grey suggestions derive from other lines and never auto-apply." />
      </h2>
      <p className="drill-hint">
        Stored values feed the engine; the chips are the sheet&apos;s formulas, offered and
        never applied for you. Clearing a field unsets that input.
      </p>
      {filingStatus !== 'single' && !split && (
        <p className="drill-hint">
          One column: add the second person in Settings → Household to split the per-person
          lines (salary, W-2, 401k, HSA, pre-tax deductions) into two. Until then these values
          are stored against the primary person.
        </p>
      )}
      {error && (
        <div className="error-banner" role="alert">
          {error}
        </div>
      )}
      {/* One entry scope for every cell the server sent: Enter/ArrowDown walks the column
          across section boundaries, and from the last cell lands on Save — so Enter here
          ADVANCES rather than submitting, and Ctrl+Enter is what saves (spec §3.4). */}
      <form
        data-entry-scope=""
        onPaste={handlePaste}
        onSubmit={(e) => {
          e.preventDefault()
          submit()
        }}
      >
        {inputs.sections.map((section) => {
          // A header is drawn only where it has something to head: a section of purely
          // household lines keeps its single full-width column and no names.
          const headed = split && section.items.some((item) => item.is_per_person)
          return (
            <div key={section.section} className="tax-section">
              <h3 className="eyebrow">{sectionLabel(section.section)}</h3>
              <div className={`tax-input-grid${split ? ' is-split' : ''}`}>
                {headed && (
                  // aria-hidden: every box already carries the person in its own aria-label,
                  // and announcing the names again would double every row.
                  <div className="tax-input-row tax-input-head" aria-hidden="true">
                    <span />
                    {columns.map(({ person, name }) => (
                      <span key={person.id} className="tax-input-person">
                        {name}
                      </span>
                    ))}
                    <span />
                  </div>
                )}
                {section.items.map((item) => {
                  const cells = cellsOf(item, columns)
                  // The chip belongs to ONE cell: derived suggestions are the primary
                  // person's (design §5.3), and the columns are ordered primary-first.
                  const suggestionCell = cells[0]
                  const shown = values[suggestionCell.id] ?? ''
                  // Offered only while it differs from what is in the box; the money form is
                  // computed once because the chip, its title and the button's all show it.
                  const suggestion =
                    item.suggested === null || item.suggested === shown
                      ? null
                      : formatCurrency(item.suggested)
                  return (
                    <div key={item.key} className="tax-input-row">
                      <span className="tax-input-label">
                        {/* The grid gives the label a wide track, but a long key can still
                            ellipsize — the title recovers the full text on hover. With two
                            boxes there is no single control for a <label> to point at, so the
                            name becomes plain text and each box names itself. */}
                        {cells.length === 1 ? (
                          <label htmlFor={`tax-input-${cells[0].id}`} title={item.label}>
                            {item.label}
                          </label>
                        ) : (
                          <span className="tax-input-name" title={item.label}>
                            {item.label}
                          </span>
                        )}
                        {item.is_derived && <span className="badge">derived</span>}
                      </span>
                      {cells.map((cell) => {
                        const value = values[cell.id] ?? ''
                        const classes = [
                          value.trim() !== '' && !isAmount(value) ? 'invalid' : '',
                          flashIds.has(cell.id) ? 'pasted-flash' : '',
                          // A household line inside a split grid takes both person tracks
                          // rather than leaving a hole under one name.
                          split && cells.length === 1 ? 'tax-input-wide' : '',
                        ]
                          .filter((name) => name !== '')
                          .join(' ')
                        return (
                          <AmountInput
                            key={cell.id}
                            id={`tax-input-${cell.id}`}
                            aria-label={cells.length === 1 ? undefined : cellLabel(cell)}
                            className={classes === '' ? undefined : classes}
                            value={value}
                            onValueChange={(next) =>
                              setValues((current) => ({ ...current, [cell.id]: next }))
                            }
                          />
                        )
                      })}
                      {/* The track is reserved whether or not a suggestion is showing, so a
                          chip appearing mid-keystroke never shifts the input under the
                          cursor. */}
                      <span className="tax-suggestion">
                        {suggestion !== null && (
                          <>
                            <span className="tax-suggestion-value" title={suggestion}>
                              suggested {suggestion}
                            </span>
                            <button
                              type="button"
                              className="chip"
                              aria-label={`Apply suggestion for ${item.label}`}
                              title={`Apply ${suggestion}`}
                              onClick={() =>
                                setValues((current) => ({
                                  ...current,
                                  [suggestionCell.id]: item.suggested ?? '',
                                }))
                              }
                            >
                              Apply
                            </button>
                          </>
                        )}
                      </span>
                    </div>
                  )
                })}
              </div>
            </div>
          )
        })}
        {pasteNote && (
          <p className="drill-hint" role="status" aria-live="polite">
            {pasteNote}
          </p>
        )}
        <div className="tax-form-actions">
          <button
            type="submit"
            data-entry-primary=""
            className="button button-primary"
            disabled={saving || changedCount === 0}
          >
            {saving ? 'Saving…' : 'Save inputs'}
          </button>
          <span className="drill-hint">
            {changedCount === 0
              ? 'No changes yet'
              : `${changedCount} change${changedCount === 1 ? '' : 's'} to save`}
          </span>
        </div>
      </form>
    </section>
  )
}
```

```tsx
  brackets,
  yearStatus,
  onSaved,
  onDirtyChange,
}: {
  brackets: TaxBracketsOut
  /** The YEAR's own status: always a tab, even before it has a single row. */
  yearStatus: FilingStatus
  onSaved: (updated: TaxBracketsOut) => void
  onDirtyChange?: (dirty: boolean) => void
}) {
  // The tab on screen, and the payload behind it. Both seed from the page's props and are
  // then this editor's own: a tab press fetches, a save re-syncs. A useState INITIALIZER, so
  // a prop replacement (the page refetching the SAME year and status) leaves half-typed
  // tables alone; only a save echo, a tab switch, or a remount re-adopts the server's rows.
  const [activeStatus, setActiveStatus] = useState<FilingStatus>(brackets.filing_status)
  const [payload, setPayload] = useState<TaxBracketsOut>(brackets)
  const [tables, setTables] = useState<Record<string, RowState[]>>(() => tablesOf(brackets))
  // Single-flight across the whole editor: one jurisdiction saves at a time, and the
  // in-flight name is what disables the others' buttons.
  const [saving, setSaving] = useState<string | null>(null)
  const [errors, setErrors] = useState<Record<string, string>>({})
  // The tab machinery's own flight and banner — a failed tab load is not a jurisdiction's
  // error, and putting it in `errors` would file it under a table nobody asked about.
  const [tabBusy, setTabBusy] = useState(false)
  const [tabError, setTabError] = useState<string | null>(null)
  // Tabs can be clicked faster than a fetch comes back; only the newest may land.
  const tabSeqRef = useRef(0)

  // JURISDICTIONS is a readonly tuple, so its .includes() takes the literal union — the
  // house cast (MonthlyUpdatePage's `STEPS.includes(stepParam as Step)`). An importer can
  // write a jurisdiction this API refuses, and a GET still returns it.
  const extras = Object.keys(payload.jurisdictions)
    .filter((name) => !JURISDICTIONS.includes(name as Jurisdiction))
    .sort()

  // The tab set: 'single' ALWAYS (the column default, the only status the importer writes and
  // the source every clone copies from), the year's own status (the one the engine walks,
  // even before it has tables), and any status that already has rows — so an MFJ table
  // entered ahead of the wedding stays reachable from a year still filed single.
  const tabs = FILING_STATUSES.filter(
    (status) =>
      status === 'single' ||
      status === yearStatus ||
      (payload.statuses_with_rows ?? []).includes(status),
  )

  // Compared as text because that IS what is in the boxes ("10." is not yet "10"), and the
  // page turns this into the confirm that guards a year switch.
  const dirty = JSON.stringify(tables) !== JSON.stringify(tablesOf(payload))
  useEffect(() => {
    onDirtyChange?.(dirty)
  }, [dirty, onDirtyChange])

  // four reload doors ask — and it asks it BEFORE the request, so a declined confirm cannot
  // leave a fetch in flight against a tab nobody opened.
  const openStatus = (status: FilingStatus) => {
    if (status === activeStatus || tabBusy) return

      !window.confirm(

      )
    ) {
      return
    }
    const seq = ++tabSeqRef.current
    setTabBusy(true)
    setTabError(null)

    // about to be replaced, and the review badges describe a clone into another status.
    setErrors({})
    setReviewFlags(null)

        if (seq !== tabSeqRef.current) return
        setActiveStatus(status)
        setPayload(next)
        setTables(tablesOf(next))
      })

        setTabError(
          err instanceof ApiError
            ? err.message
            : `Failed to load the ${FILING_STATUS_LABELS[status]} bracket tables`,
        )

        if (seq === tabSeqRef.current) setTabBusy(false)
      })
```
