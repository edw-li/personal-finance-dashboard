## Design decisions (read before coding) — and where this plan deviates from the spec's letter

**D1 — "matched months" = the savings module's rule.** The YTD card's *figure* is `/spending/yearly`'s
`cash_savings` = `savings.rollup(...)` over `MonthSavings.matched` months (spending rows present AND a
net-pay row). Its *window label* comes from `/coverage`'s `eligible_savings` (month-review eligibility);
on `finance_realdata` both are Jan–Aug 2026. The money flow uses the FIGURE's rule by calling
`savings.compose_months` + `savings.rollup` itself, so the two can never drift.

**D2 — payload fields beyond the spec's list (all additive).** The spec lists `matched_months`,
`take_home_pending_months`, `take_home_unmatched`, `take_home_unmatched_months`,
`spending_unmatched_months`, `spending_unmatched_total`. Also needed:
- `category_totals: [{category_id, name, kind, amount}]` — matched-month, cash-outflow-kind (living +
  tax) totals per category. C2.1 requires the money flow to fold by the Spending page's *all-time*
  category set, which only the client computes (one shared function); the server's own top-7 fold
  (`categories`) cannot be that set.
- `take_home_matched` — the right fan's funding (take_home_cash − take_home_unmatched), sent rather
  than subtracted in the browser (house rule: money math on the server).
- `refunds` — minus the sum of net-negative category totals (a refund category). A sankey link cannot
  be negative; without an explicit inflow node the fan would not conserve when Saved nets refunds.
- `tracking_start` — the book's first take-home month, so a pending month can be labelled "before
  tracking".

**D3 — `saved` nets refunds; `total_spend` keeps "what the fan draws".** `saved` = `cash_savings`
(transfers excluded, refunds netted — the YTD definition, spec: "match its definition exactly").
`categories` / `other_spend` / `total_spend` keep their meaning (top-7 positive fold and its gross sum)
but over the matched months. Identity: `take_home_matched + refunds − total_spend == saved`.
Three pure-service assertions and one router assertion encoded the old mixed-window/gross definition
and are updated (called out in their tasks).

**D4 — colour registry (C2).** Measured with the dataviz validator (OKLab ΔE×100, both themes):
`PALETTE[2]` (aqua) vs `POSITIVE` = 4.2 light / 8.9 dark and `PALETTE[5]` vs `POSITIVE` = 3.7 light,
so the "POSITIVE green family" is {P2, P5, POSITIVE}; `PALETTE[7]` vs `NEGATIVE` = 2.5 light.
- Kept/saved: Saved = POSITIVE; pre-tax savings = P5; ESPP = P2 (ESPP is a payroll saving —
  `PAYROLL_SAVING_KEYS` includes `espp`).
- Tax (money-flow liability node, tax-kind category, calendar tax deadlines, paycheck withholding) = P7.
- Deficit = NEGATIVE. Structural (gross, take-home, retained equity, estimates, refunds, the
  paycheck's intermediates and net pay) = MUTED. Other fold + other income = OTHER_SERIES_COLOR.
- Income: salary = P0 (+ per-person tints `[P0, SEQ[9], SEQ[3]]`), RSU = P1, ESPP = P2,
  investment/dividend income = P3. Calendar extras: cards = P4, monthly update = P6.
- Spending categories: the first tax-kind category takes P7 and goes FIRST in the fold order (stack
  bottom); the others take `CATEGORY_HUES = [P0, P1, P6, P4, P3]` in all-time rank order. That chain is
  the only 5-hue order over the non-green, non-tax slots whose every adjacent pair clears the gates in
  both themes AND which keeps Housing blue: P7–P0 29/19·30/23, P0–P1 32/27·33/28, P1–P6 27/26·29/27,
  P6–P4 20/16·21/17, P4–P3 19/13·17/10, P3–Other 20/17·17/16 (normal/CVD, dark·light). The fold is
  therefore ≤ 6 categories + Other (was 7); the Spending chart title follows the fold length.
- **Deviation (unavoidable, documented):** inside the money flow the income column (depth 0) and the
  spending column (depth 3) repeat hues (salary/Housing P0, RSU/Food P1, investment/Gifts P3): the
  chart needs ≥ 11 distinct non-grey hues and the validated palette has 8, two of which are reserved.
  Those columns are never adjacent and never linked, and every node is labelled. Within every column and
  between linked/adjacent columns no two entities share a colour (tested).

**D5 — C5 uses the objective rule only.** Spec §0: "it uses only the objective rule 'a month whose last
day is after today is in progress'". A month is partial iff `month >= first-of-month(today)`, `today` =
the frontend's `todayIso()` (the clock attention/YTD/Up-next already use). `review_state` is not used
(a past month can be `in_progress` because take-home is missing while its spending is complete).
Tooltip: "Sep 2026 — month to date (in progress)"; a future month: "… — future month (in progress)".

**D6 — C4 width measurement lives in `EChart`.** Option builders are pure and cannot know pixels.
`monthAxis` emits a *branded* formatter; `fitMonthAxes(option, containerWidth, zoom)` (pure, in
grammar.ts, unit-tested at 1280/1600/1920 card widths) picks the mode; `EChart.tsx` applies it before
`setOption`, after a resize and after every dataZoom. Non-month label sets ("2023", "Gross", dates) keep
today's exact axis (other lanes' charts untouched). `dateAxis` keeps its current output.

**D7 — Partial styling (C5):** patterns ON → the estimate hatch decal + dashed outline; patterns OFF →
`opacity 0.45` + dashed outline (spec wording; the opposite of the vesting chart's choice, which stays).

```python
# The kinds the YTD card's cash_savings subtracts (savings.py): transfers stayed yours.
CASH_OUTFLOW_KINDS = (LIVING, TAX)


@dataclass(frozen=True)
class FlowSpendingRow:
    category_id: int
    name: str
    kind: str
    amount: Decimal


@dataclass(frozen=True)
class FlowMonth:
    """One calendar month of the year: its take-home row (None = none entered) and its
    spending rows (None = no rows at all — distinct from rows that are all $0.00)."""

    month: date
    net_pay: Decimal | None
    spending: tuple[FlowSpendingRow, ...] | None


@dataclass
class MoneyFlowCategoryTotal:
    category_id: int | None
    name: str
    kind: str
    amount: Decimal


@dataclass
class MatchedWindow:
    """The right-hand side's months (2026-09-23 spec §C1)."""

    matched_months: list[date]
    take_home_matched: Decimal
    take_home_unmatched: Decimal
    take_home_unmatched_months: list[date]
    spending_unmatched_months: list[date]
    spending_unmatched_total: Decimal
    take_home_pending_months: list[date]
    category_totals: list[MoneyFlowCategoryTotal]
    cash_savings: Decimal
    tracking_start: date | None


def matched_window(year: int, months: Sequence[FlowMonth], tracking_start: date | None) -> MatchedWindow:
    in_year = sorted((m for m in months if m.month.year == year), key=lambda m: m.month)
    by_kind: dict[date, dict[str, Decimal]] = {}
    for m in in_year:
        if m.spending is None:
            continue
        kinds = by_kind.setdefault(m.month, {})
        for r in m.spending:
            kinds[r.kind] = kinds.get(r.kind, ZERO) + r.amount
    pay = {m.month: m.net_pay for m in in_year if m.net_pay is not None}
    rows = compose_months([m.month for m in in_year], by_kind, pay, {})
    matched = [r.month for r in rows if r.matched]
    matched_set = set(matched)
    period = rollup(rows)
    totals: dict[int, MoneyFlowCategoryTotal] = {}
    for m in in_year:
        if m.month not in matched_set:
            continue
        for r in m.spending or ():
            if r.kind not in CASH_OUTFLOW_KINDS:
                continue
            entry = totals.setdefault(r.category_id, MoneyFlowCategoryTotal(r.category_id, r.name, r.kind, ZERO))
            entry.amount += r.amount
    category_totals = sorted(
        (t for t in totals.values() if t.amount != 0), key=lambda t: (-t.amount, t.name, t.category_id or 0)
    )
    pay_only = [m for m in in_year if m.net_pay is not None and m.spending is None]
    spend_only = [m for m in in_year if m.net_pay is None and m.spending is not None]
    return MatchedWindow(
        matched_months=matched,
        take_home_matched=sum((pay[m] for m in matched), ZERO_CENTS),
        take_home_unmatched=sum((m.net_pay for m in pay_only), ZERO_CENTS),
        take_home_unmatched_months=[m.month for m in pay_only],
        spending_unmatched_months=[m.month for m in spend_only],
        spending_unmatched_total=sum(
            (r.amount for m in spend_only for r in m.spending or () if r.kind in CASH_OUTFLOW_KINDS),
            ZERO_CENTS,
        ),
        take_home_pending_months=[date(year, n, 1) for n in range(1, 13) if date(year, n, 1) not in pay],
        category_totals=category_totals,
        cash_savings=ZERO_CENTS if period.cash_savings is None else period.cash_savings,
        tracking_start=tracking_start,
    )
```
with a module constant `ZERO_CENTS = Decimal("0.00")` (the wire's two places, so an empty sum

```ts
  const colors = new Map<number, string>()
```

```ts
export function niceStep(value: number): number {
  if (!(value > 0)) return 1
  const exp10 = 10 ** Math.floor(Math.log10(value))
  const f = value / exp10
  return (f < 1.5 ? 1 : f < 2.5 ? 2 : f < 4 ? 3 : f < 7 ? 5 : 10) * exp10
}
export interface RobustMax { max: number; interval: number }
/** nice(p95 × 1.15), only when max > 1.5 × p95 (nearest-rank p95 over the positive values). */
export function robustMax(values: readonly (number | null | undefined)[]): RobustMax | null {
  const sorted = values.filter((v): v is number => typeof v === 'number' && Number.isFinite(v) && v > 0).sort((a, b) => a - b)
  if (sorted.length === 0) return null
  const p95 = sorted[Math.max(0, Math.ceil(0.95 * sorted.length) - 1)]
  if (!(sorted[sorted.length - 1] > 1.5 * p95)) return null
  const target = p95 * 1.15
  const interval = niceStep(target / 5)
  return { max: Math.ceil(target / interval - 1e-9) * interval, interval }
}
```

```ts
const MONTH_LABEL = /^(Jan|Feb|Mar|Apr|May|Jun|Jul|Aug|Sep|Oct|Nov|Dec) (\d{4})$/
export const MONTH_LABEL_FULL_PX = 56   // "Oct 2025" ≈ 50px at 12px system-ui + a 6px gap
export const MONTH_LABEL_SHORT_PX = 36  // "Jan '26" ≈ 39px beside a 22px "Dec", centres 36px apart
export const PARTIAL_MARK = '*'
export type MonthLabelMode = 'full' | 'short' | 'sparse'
export const monthLabelMode = (spacing: number): MonthLabelMode =>
  spacing >= MONTH_LABEL_FULL_PX ? 'full' : spacing >= MONTH_LABEL_SHORT_PX ? 'short' : 'sparse'
/** `index` is the position inside the visible window — echarts passes it relative to the window. */
export function monthTick(label: string, index: number, mode: MonthLabelMode, marked = false): string {
  const match = MONTH_LABEL.exec(label)
  if (match === null) return label
  const mark = marked ? PARTIAL_MARK : ''
  if (mode === 'full') return `${label}${mark}`
  const [, month, year] = match
  const withYear = mode === 'sparse' || index === 0 || month === 'Jan'
  return `${withYear ? `${month} '${year.slice(2)}` : month}${mark}`
}

  return formatter
}
```
